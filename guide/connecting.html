Connecting objects

place() returns a list

patch.place() always returns a list of the objects it placed, even when it placed one:

osc = patch.place("cycle~ 440")[0]        # one object: take [0]
a, b, c = patch.place("cycle~ 220", "cycle~ 330", "cycle~ 440")
voices = patch.place("cycle~", num_objs=8) # eight separate cycle~ objects

Forgetting [0] is the most common mistake: patch.place("cycle~") is a list, and a list has no .outs.

Inlets and outlets

Every object has .ins and .outs, numbered from 0, left to right, as in Max. cycle~ has two inlets (frequency, phase) and one outlet:

osc.ins[0]    # frequency inlet
osc.ins[1]    # phase inlet
osc.outs[0]   # the audio out

To see an object’s inlets and outlets, hover its stub in your editor, or print len(obj.ins) and len(obj.outs).

connect()

Each cord is a pair, (outlet, inlet). Pass as many pairs as you like in one call:

patch.connect(
    (osc.outs[0], dac.ins[0]),
    (osc.outs[0], dac.ins[1]),
)

  • Tuples are checked, lists are not. [outlet, inlet] also works, but a type checker skips it. Use tuples.

  • Midpoints. A third element bends the cord through points, as one flat list [x1, y1, x2, y2, ...], the way Max stores them: (a.outs[0], b.ins[0], [100.0, 40.0]).

  • Fan out freely. One outlet can feed many inlets, and one inlet can take many cords.

Stubs

maxpylang.objects has a ready-made object, a stub, for each of the 1,130 objects in maxpylang’s object list for Max, MSP and Jitter. Python names follow these rules:

Max name

Python name

Rule

cycle~

cycle_tilde

~ becomes _tilde

jit.movie

jit_movie

. becomes _

mc.cycle~

mc_cycle_tilde

both

2d.wave~

_2d_wave_tilde

a leading digit gets _ in front

live.dial

live_dial

- also becomes _

in, print

in_, print_

a Python keyword or built-in name gets _ after it

Operators are spelled out: *~ is times_tilde, +~ is plus_tilde. These write times~ and plus~, which Max accepts as other names for *~ and +~. A string such as patch.place("*~ 0.5") writes *~ itself and is easier to read, but only stubs are checked by a type checker.

Call a stub to give it arguments and attributes. Positional arguments become box arguments and keywords become @ attributes:

from maxpylang.objects import cycle_tilde, metro

cycle_tilde(440)        # cycle~ 440
metro(500, active=1)    # metro 500 @active 1

Some stubs have no object data behind them (array.*, string.*, v8): they are placed as unknown objects with no inlets, without a warning. If an object has no inlets after placing, check obj.notknown(); see Known issues.

Connect what place() returns, never the stub. A stub is a template; place() puts a copy in the patch. Connecting the stub itself raises:

ValueError: 'cycle~' is a stub from maxpylang.objects, which is never placed itself.
Connect the object place() returned instead, e.g. obj = patch.place(stub)[0]

Example

"""Connecting objects: stubs, tuples, many objects at once, and midpoints."""
import maxpylang as mp
from maxpylang.objects import button, counter, cycle_tilde, ezdac_tilde, flonum, gain_tilde, metro, toggle

patch = mp.MaxPatch(verbose=False)

# Stubs give autocomplete and type checking. Call one to add arguments and attributes.
patch.set_position(30, 30)
osc = patch.place(cycle_tilde(220))[0]
patch.set_position(30, 90)
gain = patch.place(gain_tilde)[0]
patch.set_position(30, 230)
dac = patch.place(ezdac_tilde)[0]

# Inlets and outlets are 0-based: outs[0] is the leftmost outlet.
patch.connect(
    (osc.outs[0], gain.ins[0]),
    (gain.outs[0], dac.ins[0]),
    (gain.outs[0], dac.ins[1]),
)

# A string works for any object and is never type-checked.
patch.set_position(200, 30)
tick = patch.place("metro 250 @active 1")[0]
patch.set_position(200, 90)
count = patch.place("counter 0 7")[0]
patch.connect((tick.outs[0], count.ins[0]))

# num_objs places several copies; each is its own object.
toggles = patch.place(toggle, num_objs=4, starting_pos=[350, 30], spacing=[40, 0])
metros = patch.place(metro(500), num_objs=4, starting_pos=[350, 90], spacing=[80, 0])
flashes = patch.place(button, num_objs=4, starting_pos=[350, 150], spacing=[80, 0])
for t, m, b in zip(toggles, metros, flashes):
    patch.connect((t.outs[0], m.ins[0]), (m.outs[0], b.ins[0]))  # each button flashes on its metro's tick

# A third element bends the cord through midpoints, as a flat list [x1, y1, x2, y2, ...].
patch.set_position(200, 160)
shown = patch.place(flonum)[0]
patch.connect((count.outs[0], shown.ins[0], [210.0, 140.0]))

patch.save("connecting")

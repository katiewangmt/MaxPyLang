Getting started

MaxPyLang writes Max patches from Python. You place objects, connect them, and save a .maxpat file that opens in Max like any patch you made by hand.

Install

python3 -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install maxpylang

You need Python 3.9 or newer. You only need Max to open the result. See Installation for installing from source.

Your first patch

"""Getting started: a 440 Hz tone, saved as hello_world.maxpat, then loaded back."""
import maxpylang as mp
from maxpylang.objects import cycle_tilde, ezdac_tilde

patch = mp.MaxPatch()

# set_position() moves a cursor; place() puts the object one grid step right of it. y grows downward.
patch.set_position(30, 30)
osc = patch.place(cycle_tilde(440))[0]  # place() returns a list; [0] is the object

patch.set_position(30, 90)
dac = patch.place(ezdac_tilde)[0]

# One cord per (outlet, inlet) pair: the oscillator into both speakers.
patch.connect((osc.outs[0], dac.ins[0]), (osc.outs[0], dac.ins[1]))

patch.save("hello_world")  # adds .maxpat

# Load the file again and list what is in it.
loaded = mp.MaxPatch(load_file="hello_world.maxpat")
for obj_id, obj in loaded.objs.items():
    print(obj_id, obj.name)

Run it with python getting_started.py. It prints what it connected, a PatchCheck report (see Checks and warnings) and the objects it loaded back, and writes hello_world.maxpat. Open that in Max, turn on audio with the speaker (ezdac~), and you hear a 440 Hz sine.

The four ideas

A patch. mp.MaxPatch() is an empty patch. mp.MaxPatch(load_file="x.maxpat") loads an existing one; it also reads Max for Live .amxd files. Until pull request #20 is released, loading fails on most patches saved by Max itself; patches written by maxpylang load fine. See Known issues.

Placing. patch.place(...) adds objects and always returns a list, even for one object, so take [0]. You can describe an object two ways:

  • a stub from maxpylang.objects: cycle_tilde(440). Your editor autocompletes it and a type checker can check its cords (see Editor setup);

  • a string with the text you would type in the box: "cycle~ 440". Works for anything, checked only for a known name.

Connecting. patch.connect((outlet, inlet), ...) draws cords. obj.outs[0] is the leftmost outlet and obj.ins[0] the leftmost inlet. See Connecting objects.

Saving. patch.save("name") writes name.maxpat. With device_type= it writes a Max for Live device instead; see Max for Live.

Laying out a patch

Without positions, objects are placed on a grid in the order you place them. For a patch people will read, call patch.set_position(x, y) before each place(). Coordinates are in pixels from the top left, and y grows downward, so signal flows top to bottom.

set_position() moves a cursor, and place() puts the object one grid step (80 px) to the right of it: after set_position(30, 30), the object lands at (110, 30). A y of 0 is moved down to 80. Only the spacing between objects matters for reading a patch, so this offset is usually harmless. Good spacing:

  • about 60 px between objects in a chain,

  • parallel chains side by side at the same y,

  • a comment just above an object to label it: patch.place("comment pitch in").

Unknown objects

maxpylang knows an object when its object data has an entry for it and the box has the arguments that entry requires. The data covers most objects in Max, MSP and Jitter, plus any packages you import (see Objects from packages). Anything else is unknown.

When you place one, you get an UnknownObjectWarning and an object with no inlets or outlets. Usually it is a typo or a missing argument; fix it. obj.notknown() tells you in code. Fix every unknown object before saving: two unknown objects in one patch overwrite each other (see Known issues).

When you load a patch that has one, for example from a package you have not imported, the object keeps its cords and saves back unchanged, but you cannot edit it. (Until pull request #20 is released, most patches saved by Max fail to load; see Known issues.) Replace it with a known object by id:

patch = mp.MaxPatch(load_file="old.maxpat")
patch.replace("obj-3", "cycle~ 440")   # keeps the cords that fit the new object

save() lists the unknown objects that remain; see Checks and warnings.

Some objects that exist in Max are still unknown to maxpylang, among them array.*, string.* and v8; see Known issues.
